# Skill Manager

本地运行的中文桌面工具，集中管理 AI 编程客户端的 Skill 与 Rule，支持项目启停与恢复、全局安装更新、分组方案和可选的 LLM 翻译解读。基于 Tauri 2、React、TypeScript 和 Rust。

## 快速开始（macOS）

当前提供 macOS 构建；Apple Silicon 与 Intel 需分别构建对应架构。Windows 尚未支持，Linux 尚未进行桌面验证。

1. 安装 Git、Node.js 24、pnpm 10.12.3、Rust stable 和 Xcode Command Line Tools。首次使用可运行 `xcode-select --install`。完整系统要求见 [Tauri 前置依赖](https://v2.tauri.app/start/prerequisites/)。
2. 克隆并安装锁定依赖：

   ```sh
   git clone https://github.com/MicroSharpAnt/Skill-Manager.git
   cd Skill-Manager
   npm install -g pnpm@10.12.3
   pnpm install --frozen-lockfile
   ```

3. 开发运行：`pnpm dev`。运行检查：`pnpm test`。生成应用：`pnpm build`。
4. 在 Finder 打开 `src-tauri/target/release/bundle/macos/`，将 **Skill Manager.app** 拖入“应用程序”。更新时先退出旧应用再替换；数据与应用分开保存。

也可运行 `pnpm build:dmg` 生成磁盘安装镜像，输出在 `src-tauri/target/release/bundle/dmg/`。构建默认没有 Apple 开发者签名或公证；下载的构建可能被 Gatekeeper 阻止，请核实来源后按系统“隐私与安全性”提示操作。发布签名说明见 [Tauri macOS 分发](https://v2.tauri.app/distribute/macos-application-bundle/)。

GitHub [Actions](https://github.com/MicroSharpAnt/Skill-Manager/actions) 会运行测试并构建 macOS 应用 ZIP，可在成功运行的 Artifacts 中下载对应架构的压缩包并解压安装（需要登录 GitHub，产物有保留期限）。这不是已签名的正式发行版。

### Codex Skill 使用统计

在 **全局 Skill → 使用统计** 查看近 7 天、30 天或全部本机日志中的 Skill 使用迹象，支持搜索、按次数/任务数/最近使用排序及手动刷新。当前仅接入 Codex，不代表其他客户端的调用次数。

读取 `CODEX_HOME`（默认 `~/.codex`）下的 `sessions` 与 `archived_sessions`，不修改日志、不上传会话内容。直接加载识别会话内 `<skill>` 注入块；读取推断识别成功返回的 `cat`、`head`、`tail`、只读范围 `sed`，支持普通工具调用与 `exec` 包装中的字面量 `tools.exec_command`。同一 Skill 在同一任务同一轮最多计一次，直接加载优先；旧日志无轮次 ID 时按任务去重。软链接按当前真实路径归并，同名不同来源分开显示。

读取可能用于审阅或编辑，因此次数是使用迹象，不能等同成功执行次数。复杂 shell、未输出退出状态的包装、脚本/其他工具读取、上下文复用及缺失日志可能漏计；未发现记录显示“无数据”。页面显示日志覆盖范围与解析警告，历史已移除技能仍可在统计中查看。解析结果按文件大小和修改时间缓存在应用内存中，刷新只重新解析变化的日志。

只读命令行核验：`cargo run --manifest-path src-tauri/Cargo.toml --no-default-features --offline --example codex_usage -- 30`（时间范围为 `7`、`30` 或 `0`）。

一个本地运行的中文 Tauri 桌面应用。参考 cc-switch 的目录扫描、资源分组和状态展示逻辑，重点解决项目 Skill / Rule **开发时关闭、提交前恢复**的问题。

## 当前可用功能

- 添加多个 Git 项目，分别管理资源。支持 Cursor (`.cursor/skills`)、Codex (`.agents/skills`)、Claude (`.claude/skills`)、DeepSeek Harness (`.dsh/skills`)、ZCode (`.zcode/skills`) 和 Kimi (`.kimi/skills`) 的项目 Skill，以及 Cursor `.cursor/rules/*.mdc`。
- 读取名称、描述与正文，搜索、类型和状态筛选；正文只读。项目、全局、远端详情和重复 Skill 预览支持 Markdown 排版（标题、列表、表格、引用和代码块），YAML 元信息可展开查看。
- 单项或批量启停。一个 Skill 目录（含 references、scripts 等）是完整单元，一个 Rule 文件是一个单元。
- 多重分组、保存和应用工作场景。场景记录关闭集合；发生变化后显示“自定义”。
- “提交前全部恢复”还原所有关闭项；恢复中心处理已关闭资源及中断的批次。
- 本地 pre-commit 拦截未恢复资源、未完成操作和损坏清单；保留已有 Hook，在明确确认后备份、串联。
- 全局 Skill 的六客户端软链接矩阵：Claude、Codex、DeepSeek Harness、OpenCode、ZCode、Kimi。扫描共享库和客户端已有链接，同一真实源合并展示，同名不同来源分开显示。
- **修复断链**：选择目标技能目录，按同名文件夹匹配断开的全局 Skill 软链接；列出原指向、新指向和无法匹配的原因，支持单选／全选可修复项。核对预览后备份原链接并重建，可在备份中心回退。
- **重复检查**：识别不同实际目录中的同名 Skill，比较完整文件树和权限；选择保留源后，批量预览将相同副本备份并替换为软链接。支持任意两份来源的逐文件、逐行 Diff，显示增删行、行号、权限与换行格式，比较窗口内可直接选择保留左侧或右侧，并预览将另一份备份后改为软链接；也可选择“仅保留所选版本”，备份移除其他版本并统一客户端入口，支持在备份中心预览整批回退。
- 全局本地目录导入、skills.sh 在线搜索、GitHub 仓库扫描与安装。点击搜索结果名称或“查看详情”先阅读完整 SKILL.md、来源和文件清单，再选择预览安装；已有同名 Skill 也能查看远端详情。
- 安装技能搜索会按记录的下载源或升级来源（仓库＋实际 Skill 路径）匹配本地版本，自动显示“无需更新”“可更新”“本地有修改”或检查失败。比较覆盖完整文件树；搜索比较仓库 HEAD，直接读取仓库时比较所选分支或标签，因此“可更新”表示内容存在差异，不保证版本号更高。同仓库只下载一次，不下载无已记录本地来源的仓库。详情页匹配单一本地版本后可直接比较并更新，保留原下载来源和备份；多个版本需显式选择，无法确认路径时不会按同名自动覆盖。
- 关联仓库、分支及精确 Skill 子目录后检查更新；预览升级、本地修改确认、完整旧版本备份及恢复。链接客户端随共享源一起更新。

项目和全局入口互相独立，项目资源继续采用 Git 私有目录暂存；全局资源采用共享源加客户端软链接。

## 外观与快捷操作

首页右上角的主题按钮提供 **信号蓝、松针绿、琥珀灰、夜航** 四套工作台预览，点击即切换，重启后保留。导航、面板、代码正文和状态颜色一起变化。

全局 Skill 列表同时显示当前目录和下载来源。详情中可点击下载仓库或当前升级仓库，在浏览器打开对应分支和子目录。新安装会单独保存最初的远程来源或本地导入路径，后续关联升级仓库不会覆盖它；历史没有记录的来源显示“来源未记录”，不按同名 Skill 猜测网址。

项目资源和全局 Skill 列表按分组显示可折叠层级，展开分组可直接查看成员，未分组资源单独列出。全局分组使用色块选色，分组标题整行和筛选菜单使用对应颜色背景；搜索或切换筛选时自动展开匹配分组。拖动 Skill 名称左侧手柄到目标分组（也支持折叠组和未分组），即可保存分组归属，不移动实体文件。创建分组位于分组筛选右侧，检查更新位于“搜索与安装”右侧。

Skill 查看面板支持拖动左边缘调整宽度，自动记住宽度；双击拖动条恢复默认，也可聚焦拖动条后用左右方向键微调。

使用 `⌘ K`（或 `Ctrl K`）聚焦当前页搜索；搜索框可清空，筛选可一键重置。列表支持半选提示，批量操作栏会注明筛选外的选中数量。全局分组、仓库和备份可从主页直接进入，管理弹窗内也可搜索 Skill。切换项目／全局页面会保留全局查询与选择。

弹窗按 `Esc` 逐层关闭；`Tab` 在当前弹窗内移动，跳过禁用项。场景／分组名称输入后可按 Enter 保存。

## 使用

1. 打开 Skill Manager，选择 Git 项目目录。添加项目只保存管理器自己的记录，不改项目文件。
2. 点击“启用保护”，安装本地提交检查。已有 pre-commit 时，应用会显示备份及串联说明。
3. 选中资源，点击“批量关闭”，核对变更清单后执行。也可以保存分组，或将当前启用状态保存为工作场景。
4. 提交代码前点击“提交前全部恢复”，再检查 Git 差异并正常提交。

例如，`.agents/skills -> ../.cursor/skills` 是同一份资源的另一个入口，因此不重复纳管；在 Cursor 源目录关闭某个 Skill 时，Codex 链接入口也随之不可见。`AGENTS.md` 保持独立生效。

## cc-switch 功能与独立迁移

全局入口的 **迁移与管理** 提供 cc-switch 迁移、全局分组、仓库订阅、ZIP / `.skill` 批量导入、备份中心、存储与客户端目录设置、软链接/复制方式、未管理资源接管和批量启停/卸载。

迁移页默认目标为 `~/.skill-manager/skills`。填写 cc-switch 数据目录（通常为 `~/.cc-switch`），先扫描预览；核对范围并退出 cc-switch 后执行。源文件、已有链接、分组、仓库和更新来源一起迁入。原数据库不会改写，历史备份复制到本应用目录。

完整对照见 [CC-SWITCH-PARITY.md](docs/CC-SWITCH-PARITY.md)。

客户端默认目录依据 [ZCode 官方文档](https://www.zcode.network/cn/docs/skill/) 和 [Kimi 官方文档](https://github.com/MoonshotAI/kimi-cli/blob/main/docs/en/customization/skills.md)：`~/.zcode/skills`、`~/.kimi/skills`，可在“存储与客户端”中自定义。Gemini、GrokBuild、Hermes、Pi 已停止支持，已有文件和软链接保留；旧方案读取时忽略这些客户端，若无剩余目标需重新选择。

更新与恢复预览支持文本 Diff：默认左右并排显示当前本地版与待安装版，可切换逐行对比；展示行号、红色删除和绿色新增，并可按文件查看 SKILL.md、辅助文件、权限和换行差异。二进制或超大文件会说明无法生成文本 Diff。预览后内容变化会阻止读取过期 Diff 和应用更新，需重新预览。

## 全局 Skill 使用

1. 打开“全局 Skills”，已有资源会自动扫描。点击矩阵中的 `+` 为客户端创建软链接；点击已链接按钮关闭该客户端，源文件保留。
2. “发现 Skill”支持 skills.sh 关键词搜索，或直接输入 `owner/repo` 和分支（默认 `HEAD`）。读取仓库后选择准确的 Skill 子目录，预览并安装。
3. 新资源安装在当前共享库；独立迁移后为 `~/.skill-manager/skills/<name>`。安装后在客户端矩阵中选择要启用的客户端。也可导入本地包含 SKILL.md 的目录。
4. “检查更新”优先使用升级来源，未关联时自动使用最初下载的远端来源。版本标签（如 `v1.0.60`）会查询 GitHub 更新的稳定发布版；分支及提交引用保持原引用。检查和预览使用同一版本解析规则，界面汇总已检查、可升级、失败及无来源数量。已有本地 Skill 可在详情中“关联升级来源”，选择仓库及子目录；首次关联会按覆盖本地版本处理并保留备份。
5. 详情中可预览升级、恢复历史版本。检测到本地修改时必须勾选确认，备份包含完整目录而不只是 SKILL.md。
6. 首页点击“修复断链”，选择存放 Skill 的父目录（例如 `~/.skill-manager/skills`），点击“扫描匹配”。勾选所需条目或“全选可修复项” → “预览修复” → 核对并勾选确认 → “确认修复软链接”。仅匹配直接子目录中的同名 Skill，目标须含有效 `SKILL.md`。

全局数据保存在应用自己的 `Application Support/com.yangjie.skillmanager/global/` 中：SQLite 来源与链接状态、操作日志、安装预览和完整版本备份。常规操作不访问 cc-switch 数据库；迁移预览使用只读连接读取 Skill 专用表，绝不改写原库。请保留备份和未完成操作日志。

关闭全局资源只移走属于该源的客户端投影，不移走实体源目录。同名外来目录、其他源的链接以及断链会提示冲突，不会覆盖。本地“导入”保留原目录；“接管到独立库”可在预览后移动实体源并替换原客户端入口。支持 Skill 内指向本 Skill 内部的相对软链接；拒绝越界链接、嵌套 Git 目录和特殊文件。

升级以不可覆盖的原子移动替换共享源，保留旧版本；操作日志支持失败回滚与重启恢复。源和应用数据需要在同一文件系统，否则移动会安全失败。已取消的预览与下载缓存可在存储页清理；备份和迁移历史单独保留。

## 文件与 Git 保护

关闭不是删除内容，而是使用原子、不可覆盖的 rename，将资源移至当前 worktree 的 Git 私有目录：

```text
<git-dir>/skill-manager/
  state.json         原路径、内容/权限哈希、HEAD、资源 index 指纹
  resources/         完整暂存内容（路径 SHA-256 为目录或文件名）
  transaction.json   仅操作期间存在的预写恢复日志
  ready.hash         全部恢复后才签发的提交检查凭据
  RECOVERY.md        无需依赖应用的手动恢复说明
  lock               跨进程互斥锁
```

工作树与 index 的关系保持原样：支持关闭前的未暂存、已暂存和未跟踪内容；不会自动执行 `git add`、`reset`、修改 skip-worktree/assume-unchanged 标志。Git 在关闭期间仍会显示删除，这是文件暂存的正常结果。

批量操作先全部预检，再写日志，然后逐项移动；失败按相反顺序回滚。中断后日志保留，提交仍被拦截。恢复时检查 HEAD、资源 index 和内容哈希；原路径出现新文件、分支发生变化或删除被暂存时会拒绝覆盖，并显示修复方法。

`ready.hash` 绑定空暂存清单，清单丢失或损坏会阻止提交。`--no-verify` 和直接操作 Git 对象能够显式绕过 Hook，保护不替代提交前的 diff 检查。

## 支持边界

- macOS 优先；核心的不可覆盖移动也支持 Linux，但仅提供经过构建验证的 macOS 应用。
- worktree、submodule 的 `.git` 文件会正确解析为各自私有 Git 目录。worktree 共用 Hook，安装后需要为每个 worktree 初始化保护，否则该 worktree 普通提交也会被拦截。
- 自定义 `core.hooksPath` 不自动接管；此版本不开放该项目的启停功能。
- 项目 Skill 内的软链接和嵌套 Git 仓库不移动。链接形式的顶层客户端目录跳过并提示管理其源目录。外部目标不会被遍历后修改。
- `AGENTS.md`、`CLAUDE.md`、`.cursorrules` 只提示，不关闭或编辑。
- 不自动更改分支或修复用户的暂存区。关闭后暂存删除时，应先撤销相应路径的暂存变化，再恢复；不要丢弃其他文件的暂存内容。
- 管理器文件数据库保存项目列表、分组和场景；恢复文件独立保存在 Git 私有目录。请不要手动清理仍有关闭资源的 `skill-manager` 目录。
- 全局管理支持默认和自定义客户端目录、公开 GitHub 仓库、ZIP / .skill 导入。升级来源可从 cc-switch 迁入或手动关联，不凭目录名称猜测仓库子路径。OpenClaw 作为扫描来源，客户端插件市场和私有 GitHub 认证不在此界面范围。

## 开发与构建

本机验证环境：Node.js 24.19、pnpm 10.12.3、Rust 1.98、Git，以及 Xcode Command Line Tools。其他系统需要对应的 Tauri 系统构建依赖。

```sh
corepack pnpm install --frozen-lockfile
corepack pnpm dev
corepack pnpm test
corepack pnpm build
```

输出：`src-tauri/target/release/bundle/macos/Skill Manager.app`。此构建不使用开发者签名或公证。

离线构建仅适用于已经完整安装本项目依赖的电脑：使用 `pnpm install --offline --frozen-lockfile` 和 `CARGO_NET_OFFLINE=true pnpm build`。首次安装需要联网。`scripts/bootstrap-offline.sh` 是历史缓存恢复工具，不属于标准安装流程。

仅检查项目，不启动 UI，也不修改仓库：

```sh
cargo run --manifest-path src-tauri/Cargo.toml --no-default-features --offline --example inspect -- /path/to/project
```

`npm run dev:web` 是只读界面预览，没有文件控制能力。可选的 `public/preview.json` 只供本地预览，交付构建前应移走；桌面应用在在线搜索、读取仓库、检查更新和下载时请求 skills.sh / GitHub；主动使用 LLM 功能时还会请求用户配置的接口。

## 验证

`src-tauri/tests/project_safety.rs` 使用真实临时 Git 仓库测试原样恢复、文件权限、部分暂存、批次预检、失败回滚、损坏清单、外部改动、已有 Hook、worktree、submodule、软链接、嵌套仓库和中断恢复。测试不会操作真实项目。

`src-tauri/tests/global_safety.rs` 验证全局链接归属、批次冲突、内部链接、升级预览失效、本地修改保护、失败回滚、中断恢复及归档路径安全。全局测试使用独立临时 HOME，不操作真实全局 Skill。

显式联网验证（所有安装、升级和链接也都在临时 HOME 中）：


## LLM 翻译与解读

侧栏的 **设置** 可配置 OpenAI 兼容 API 的基础地址、API Key 和模型名称。支持通过服务的 `/models` 接口获取模型，也可手动填写。基础地址应包含服务要求的版本路径；完整 `/chat/completions` 地址也会自动归一化。只有点击获取模型或生成结果时才发起请求。

项目 Skill / Rule 和全局 Skill 的详情提供 **原文 / 翻译 / 解读概览** 三种视图。翻译默认使用简体中文，也可选择其他语言；翻译正文并原样保留 YAML 元信息。解读概览说明用途、适用场景、关键规则、输入输出与依赖。两种生成操作均不修改资源文件，生成结果仅在当前详情中保留。

译文可编辑，点击 **用译文覆盖原文…** 核对前后内容后写入。覆盖前校验原文未变化、保留文件权限并备份到应用数据目录的 `translation-backups/`。当前详情可撤销本次覆盖；关闭详情后仍可使用显示的 `.md` 备份文件手动恢复。项目资源已关闭或有未完成恢复操作时禁止覆盖；先启用再操作。全局覆盖修改源文件，软链接立即生效，已有复制副本不会同步修改。解读概览没有覆盖入口。

API Key 存储在应用数据目录的 `llm.json`（macOS 权限 0600），不在前端存储或配置读取结果中回显。更换地址后须重新输入密钥，或明确清除以使用免密服务。请求不跟随重定向，每次请求超时为 120 秒（多批翻译的总耗时可能更长）。文档与生成结果上限为 256 KiB；截断响应不作为可覆盖结果。点击生成会将当前文档发至用户配置的服务，文档内容按待翻译/解读的数据处理。

协议参考：[Chat Completions](https://developers.openai.com/api/reference/resources/chat) 与 [模型列表](https://developers.openai.com/api/reference/resources/models/methods/list)。本地模拟服务测试覆盖模型获取、请求格式、密钥处理、元信息保留、错误与截断响应，以及项目和全局覆盖恢复；真实服务需用户填写配置后使用。

翻译显示支持 **逐句对照**（每句原文下方显示译文）、**左右对照**、**仅译文**。在 设置顶部选择风格，选择后自动保存并立即应用于已生成的译文，无需再次请求模型。默认逐句对照；标题、列表、表格和代码结构保持可读。翻译按原文句子编号分批请求，校验返回编号、漏译以及代码/链接是否变化后组装完整译文。手动编辑会使逐句映射失效，此时先显示左右对照，重新翻译后恢复逐句显示。覆盖写入的始终是纯译文，不会把对照视图中的英文一并写入。

逐句对照检查：`node --experimental-strip-types --test tests/translation.test.mjs`（Node.js 22.6+）；后端模拟接口检查：`cargo test --manifest-path src-tauri/Cargo.toml --no-default-features --offline --test llm`。

所有应用设置统一由 `SettingsPanel` 右侧面板承载，现有分区为外观主题、翻译显示风格和 LLM 接口。侧栏“设置”、文档工具栏及“去配置”均打开同一面板；不再弹出独立设置对话框。新增设置应加入此面板的对应分区。设置面板可调整宽度，关闭后保留原文/译文阅读状态；保存 LLM 配置后面板保持打开。

概览使用流式返回，收到正文即显示，并提示连接、等待或思考状态及已等待秒数；兼容只返回完整 JSON 的服务。翻译每批最多 8 句、最多两批并行，逐批显示译文与完成句数；未完成部分保留原文，全部完成前不能编辑或覆盖。停止等待后保留预览、忽略晚到结果且不再发起后续批次，已发送的请求可能仍在服务端执行。DeepSeek V4 默认关闭深度思考以减少等待，可在设置的 LLM 接口中开启；此参数仅发送给 DeepSeek V4 模型。


### LLM 冲突检查、质量检查与改进意见

项目 Skill / Rule 和全局 Skill 的详情新增三个独立视图，复用设置中的 LLM 接口和流式进度。点击对应视图的开始按钮生成报告；结果仅保留在当前详情，不写入资源文件。

- **冲突检查**：默认检查当前文档内部矛盾；可搜索并选择同一项目或全局列表中最多 8 份对照文档，检查同时生效时的指令冲突。选中后点击开始才会读取并发送文档，不自动收集整个项目。报告要求包含双方原文依据、行号、共同适用条件、影响与处理建议，区分确定冲突、条件性冲突和信息不足。
- **质量检查**：检查触发条件、规则清晰度、流程完整性、输入输出、依赖、失败处理和可验证性，按严重程度列出原文依据与修复建议。
- **改进意见**：提供按优先级排列的最小修改建议、改写示例、收益和验证方法，标明行为变化与待确认假设。

检查内容附文档编号与行号，包含 YAML 元信息，序列化后总量不超过 256 KiB。更改对照选择会清除旧冲突结果；读取失败时不发送不完整的文档集合。停止或生成失败后保留的正文标为未完成，可重新生成。报告属于 LLM 分析，应核对引用和实际生效范围；未提供的引用文件、链接及运行环境不会自动验证。

### 分组操作

项目分组标题右侧提供整组开关；全部开启时点击关闭，全部关闭或部分开启时点击开启。整组操作包含搜索、类型和状态筛选之外的成员，沿用资源变更预览、Git 提交保护和完整暂存恢复机制。存在冲突、异常或不支持的成员时，先处理异常再切换整组。

项目资源支持拖动行或拖动手柄归组；拖动已选资源时移动整个选择集。右键资源可查看详情、批量启停或移动分组；右键分组可重命名、改色、选择整组和删除分组。删除分组保留资源，移动分组不改变启用状态，工作场景保持独立。已有资源可以属于多个分组；显式“移动”会从原有分组移除并加入目标分组。分组手柄支持拖动排序和上下方向键，顺序与颜色保存在本地数据库。

全局 Skill 分组标题在每个客户端列提供独立开关，右键菜单也有相同入口。切换仅影响指定客户端的可切换成员，不改变其他客户端和共享源；实体源、冲突、修改过的投影保持原样，并显示不可切换数量。操作复用全局批次预检、备份与回滚机制。

### 预设方案

项目资源与全局 Skill 均支持新建、编辑、复制、删除和应用预设方案。方案按项目分别保存，全局方案独立保存，并可选择一个或多个目标客户端。原有项目工作场景会自动迁移为方案，保留原来的关闭清单和其他资源开启的语义。

方案可组合分组与单项设置，例如：方案一关闭 A、B 分组及未分组的某个 Skill；方案二开启 A、B，关闭 C。单项设置优先于分组；未配置资源默认保持当前状态，也可设为全部开启或全部关闭。分组按应用时的当前成员展开，所以以后加入组内的资源也会遵循该组设置。项目还可将当前状态保存为方案。

选择方案后点击“应用方案”，核对开启/关闭清单并确认应用。保存和编辑方案不会立即操作资源，删除方案也不会改变已应用的状态。界面显示待应用数量或“当前状态符合方案”，并记住当前选择。分组重名不影响引用，重命名后仍按分组 ID 关联。

资源缺失、已删除分组、互相冲突的分组设置和不可切换的客户端状态会阻止执行，并展示原因；可用单项设置解决重叠分组冲突。实体源目录不能被方案关闭，但可通过单项“开启”保留它。项目应用沿用文件暂存、恢复和 Git 提交保护；全局方案的开启与关闭合并为一个事务，整批预检并在失败时回滚，不拆成逐项操作。
