参考 cc-switch 的 `src/lib/api/skills.ts`、`src/components/skills/`、`src/components/settings/Skill*Settings.tsx` 及 Rust Skill 服务。对照的是用户能使用的 Skill 功能；不提供 cc-switch 的同名 IPC API，也不接管其 Provider、MCP 或代理服务。

## 独立迁移路径

默认迁移目标为 `~/.skill-manager/skills`。操作只在用户查看预览并确认执行后发生：

1. 用只读 SQLite 连接读取 cc-switch 的 Skill、分组、仓库表，读取 Skill 专用目录设置。
2. 按 cc-switch 的存储设置定位真实源。多个来源不合并覆盖；缺失内容和来源解析不确定项明确提示。
3. 保留原 Skill 元数据（含原 ID、安装时间、更新哈希等），从 readme URL 解析准确分支与子目录。未知路径不按同名猜测。
4. 预览记录管理状态、源内容、目标占用、链接原始目标和父目录身份，执行前重新检查。复制过来的历史备份也保留来源与客户端期望状态。
5. 写入日志后执行不可覆盖移动；重建现有软链接。数据库中的启用期望与实际链接不一致时，保留期望并提示，不强占冲突路径。
6. 只更新本工具自己的数据库；保留 cc-switch 数据库及原历史备份。迁移后的全局管理不依赖 cc-switch 的数据库。
7. 失败按日志回滚，重启可恢复；后续状态未变化时，可在历史记录中预览整批撤销迁移。

迁移时退出 cc-switch，避免两个工具同时重写相同链接。迁移后不要再让 cc-switch 操作这些已迁出的 Skill。

## 明确边界

- Skill 相关功能通过本工具自己的界面提供；不会抢占系统中已注册的 `ccswitch://` 协议。分享链接使用粘贴导入。
- macOS 优先。源目录和应用数据需要在同一文件系统，跨文件系统原子移动会安全失败。
- 不把不同来源的同名内容自动合并。外部客户端目录已修改的副本不覆盖；卸载时保留为未管理的本机资源。
- 项目目录的规则与全局不同：项目内软链接资源仍按原有项目保护边界处理。
- 私有 GitHub 认证、客户端插件市场本体及 Provider/MCP/代理配置不是此 Skill 管理界面范围。
